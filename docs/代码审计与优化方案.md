**范围**: 完整 pipeline (site detection → training → generation → evaluation)

## 一、发现的 Bug

### B1 [中等] drugflow_esfield_guide.py: `os.chdir()` 永久修改工作目录

```python
# Line 181
os.chdir("/root/baselines/DrugFlow/code/DrugFlow-main")
```

**问题**: 函数返回后 CWD 被永久改变。后续代码中所有相对路径都会使用 DrugFlow 目录，导致文件找不到。

**修复**: 使用 `contextlib.chdir` 或手动 save/restore。

### B2 [中等] drugflow_esfield_guide.py: 猴子补丁 torch.load

```python
# Line 179
_torch.load = lambda *a, **kw: _orig_load(*a, **{**kw, 'weights_only': False})
```

**问题**: 全局替换 `torch.load`。任何后续加载模型的代码都会强制 `weights_only=False`，这是不安全的（可能导致 pickle 反序列化漏洞）。

**修复**: 只在实际 load 调用处传递 `weights_only=False` 参数。

### B3 [低] quality_constrained.py: 未使用的变量

```python
# Line ~39 (approximate)
posu_result = compute_posu(molecules[0], site_map) if molecules else {"posu": 0.0}
```

**问题**: 从 `molecules[0]` 计算 POSU，然后只用了 dict 键，实际值被忽略。而且如果 `molecules` 为空会得到 dict 不是数字。

### B4 [低] site_blindness.py: Spearman 依赖 scipy

```python
from scipy.stats import spearmanr
```

**问题**: scipy 未在项目依赖中声明。如果 scipy 不可用，SQD 计算会崩溃。

### B5 [低] drugflow_esfield_guide.py: per-sample generation 循环

```python
for i in tqdm(range(args.num_samples)):
    rdmols, _, _ = model.sample(new_data, n_samples=1, ...)
```

**问题**: 每个 sample 重复处理 protein（浪费计算），且 `torch.cuda.empty_cache()` 每次都同步 CUDA。

## 二、性能瓶颈

### P1 [严重] per-sample generation × empty_cache

- 当前: 20 samples × 每次 empty_cache = 20次 CUDA 同步
- 影响: ~15-20% 额外耗时
- 修复: 移除 `empty_cache()`。如果真的 OOM，减小 `timesteps` 或 `mol_size`

### P2 [中等] n_samples=1 循环

- 当前: 逐样本生成，每次重建 protein encoding
- DrugFlow 支持 `n_samples > 1` 批生成
- 修复: 使用 `n_samples=5` 分批生成（减少 protein re-encoding）
- 保守估计加速: 30%

### P3 [中等] torch.cuda.empty_cache() 每样本调用

- 每次调用强制 CUDA 同步 + 缓存驱逐
- 对 50-step ODE 而言，需要多次 re-allocation
- 移除后预期加速: 10-20%

### P4 [低] ESFieldGuide.__call__ 中的 tiling

- 当前: n_atoms × n_sites × n_atom_types 全排列
- 34×15×11 = 5610 行 × 50 steps = 280,500 次 potential forward
- 对当前规模（34 atoms, 15 sites）可以接受
- 对大规模（100+ atoms, 20+ sites）才会成为问题

## 三、显存估算 (24GB RTX 4090D)

| 组件 | 估算显存 |
|------|---------|
| DrugFlow model (12.1M params, fp32) | ~400 MB |
| DrugFlow optimizer states | 0 (eval mode) |
| Potential network (~300K params) | ~2 MB |
| Pocket encoding (1 protein) | ~50 MB |
| Ligand + gradients (34 atoms × 50 steps) | ~100 MB |
| ESFieldGuide tiling (5610 × 86D) | ~2 MB |
| ODE solver intermediates | ~200 MB |
| CUDA context + overhead | ~1 GB |
| **总计** | **~1.8 GB** |

**结论**: 24GB 绰绰有余。安全边际 ~13×。

### 批生成优化后

| 组件 | 估算显存 |
|------|---------|
| 5 samples 同时生成 | ~2.5 GB |
| 10 samples 同时生成 | ~4 GB |
| 20 samples 同时生成 | ~7 GB |

批大小 10 是安全且高效的。

## 四、参数优化建议

### Training 参数

| 参数 | 当前 | 建议 | 理由 |
|------|------|------|------|
| hidden_dim | 128 | 128 | 无需增大，AUC 已 0.998 |
| num_layers | 4 | 4 | 足够 |
| epochs | 200 | 150 | loss 在 epoch 100 后 plateau |
| batch_size | 512-1024 | **2048** | 24GB 显存可以，加速训练 |
| lr | 1e-4 | 1e-4 | 合适 |
| displacement_threshold | 5.0Å | **4.0Å** | 5.0 太宽（v4 过拟合），4.0 更精确 |
| HEW max_pos | 4 | **3** | 减少噪声 |
| SW strength_mult | 0.5 | 0.5 | 保守，正确 |

### Generation 参数

| 参数 | 当前 | 建议 | 理由 |
|------|------|------|------|
| timesteps | 50 | **40** | 减少 20% 生成时间 |
| λ sweep | {0, 0.5, 1.0, 2.0, 5.0} | {0.1, 0.3, 0.5, 0.7, 1.0, 1.5, 2.0} | 更高分辨率，发现甜点 |
| guidance_start | 0.3 | 0.4 | 延迟 guidance，给分子更多时间成形 |
| guidance_end | 0.90 | 0.85 | 不要太晚，避免最终步不稳定 |
| grad_clip | 1.0 | 1.0 | 合适 |
| samples/pocket | 20 | 20 | 统计最小要求 |

### 批生成配置

| 配置 | 值 | 理由 |
|------|-----|------|
| batch_size | 5 | 显存安全（4GB），4× 快于逐样本 |
| 20 samples 分 4 批 | 4 × 5 | 总时间 ~50s/pocket |
