## 二、已发现并修复的问题（8 项）

### 严重问题

#### 1. `src/generation/adapt_generator_interface.py:75` — 命令行参数名拼写错误

**问题**：`--multilple_values_file` 中 `multilple` 拼写错误（多了 "lpl"），应为 `multiple`。导致运行 RepMolFlow baseline 时传入不被识别的参数名，命令执行会失败。

**修复**：改为 `--multiple_values_file`。

---

#### 2. `src/data/build_atom_site_pairs.py:79` — 负样本数量计算逻辑错误

**问题**：
```python
# 原代码
target_count = max(
    len(positives) * cfg.negative_ratio,
    min(len(ligand_atoms) * len(site_map.sites), cfg.negative_ratio)
)
```
内层 `min(所有可能pair数, cfg.negative_ratio)` 不当—— `cfg.negative_ratio` 是比值（默认 3），不是数量上限。对于典型数据（20 个原子 × 10 个位点 = 200 个可能 pair），`min(200, 3) = 3`，完全失去约束意义。

**修复**：
```python
target_count = min(
    len(positives) * cfg.negative_ratio,
    len(ligand_atoms) * len(site_map.sites)
)
```

---

#### 3. `src/site_detection/merge_sites.py:62-66` — 加权质心用复制坐标近似，存在舍入误差

**问题**：用 `[site.center] * round(weight * 10)` 复制坐标点来模拟加权平均。当 `confidence × 10` 不是整数时（如 0.75 × 10 = 7.5 → round 到 8），会产生舍入误差。

**修复**：改为精确的浮点加权平均：
```python
weights = [max(site.confidence, 0.01) for site in cluster]
total = sum(weights)
center = (
    sum(site.center[0] * w for site, w in zip(cluster, weights)) / total,
    sum(site.center[1] * w for site, w in zip(cluster, weights)) / total,
    sum(site.center[2] * w for site, w in zip(cluster, weights)) / total,
)
```

---

#### 4. `src/site_detection/build_crystal_water_sites.py:49` — 空 protein_atoms 的边界处理

**问题**：`min(distance(...) for atom in protein_atoms, default=999.0)` — 如果 PDB 中只有水没有蛋白原子（或全被过滤），`protein_atoms` 为空，default=999.0 会让所有水通过 clash 检查，产生错误结果。

**修复**：提前检查 `protein_atoms` 是否为空并显式报错：
```python
if not protein_atoms:
    raise ValueError("no protein atoms found in PDB; cannot build water sites")
```

---

#### 5. `src/utils/chemistry.py:110` — `incompatible_atom_type_for_site` 中 high_energy_water 的 atomic_number 不正确

**问题**：返回 `("charged", 7)`，其中 atomic_number=7（氮）。但在 `is_compatible_atom_site()` 中，高能水位点对 atomic_number ∈ {7, 8, 15, 16} 有兜底兼容判定。因此这个"不兼容"类型实际上会被判为兼容，type corruption 失效。

**修复**：改为 `("charged", 6)`（碳），atomic_number=6 不在 {7, 8, 15, 16} 中，确保不被兜底兼容。

**修复**：改为 `source="crystal_water_rule"`。

### 文档问题

#### 8. `docs/USAGE.md` — 全文件 Windows 路径分隔符

**问题**：所有命令使用 Windows PowerShell 语法（`$env:PYTHONPATH`、反斜杠路径 `data\raw\...`、PowerShell backtick 续行符 `` ` ``），在 Linux 服务器上无法直接执行。还包含 Windows 绝对路径 `F:\202605\WFM\...`。

**修复**：全部转为 Linux bash 语法（`export PYTHONPATH`、正斜杠路径 `data/raw/...`、移除 backtick 续行符），Windows 外部路径替换为 Linux 对应路径（`/root/autodl-tmp/...`、`/root/RepMolFlow`）。

## 四、租卡前仍需解决的问题

| 阻塞项 | 说明 |
|--------|------|
| **base generator 不匹配** | RepMolFlow 是 QM9 property-conditioned flow matching 模型，根据分子性质（如 α 极化率）生成小分子，不以蛋白口袋为条件。不能用于 SBDD 的 pocket-conditioned 生成。需要换成真正的 pocket-conditioned 3D diffusion/flow model |
| **依赖未安装** | PyTorch（训练+guidance）、RDKit（QED/SA score）、fpocket（疏水空腔检测）、Vina（docking 评估）均未安装 |
| **数据未解压** | downsampled CrossDocked 压缩包在 `/root/autodl-tmp/data/` 下，未解压和预处理 |
| **guided generation 未集成** | `run_guided_generation.py` 只写 metadata，未将 guidance hook 插入真实采样循环 |

**结论**：代码质量已达到可交接状态，但在租卡跑实验之前，必须先解决 base generator 替换这个根本性方法问题。
