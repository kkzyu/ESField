## 二、`src/utils/` — 基础工具层（无外部依赖）

### `structure_io.py` — PDB/SDF 结构读写

**核心数据类：`StructureAtom`**

```python
@dataclass(frozen=True)
class StructureAtom:
    index: int                       # 在读取顺序中的 0-based 索引
    name: str                        # PDB atom name（如 "CA"）或生成的名称
    element: str                     # 归一化元素符号（"C"/"N"/"O"/"CL" 等）
    coord: tuple[float, float, float]  # 3D 坐标
    residue_name: str                # 残基名（"ALA"/"HOH"/"LIG"）
    residue_id: str                  # 残基编号
    chain_id: str                    # 链标识
    record_name: str                 # "ATOM" 或 "HETATM"
```

**`read_pdb_atoms(path, include_hydrogen=False)`** — PDB 解析器：
- 按 PDB 标准列宽解析：atom name(12-16)、residue name(17-20)、chain(21)、residue ID(22-27)、x(30-38)、y(38-46)、z(46-54)
- 元素优先从列 76-78 读取，缺失时从 atom name 推断（如 "CA"→"C"、"CL"→"CL"）
- 默认排除氢原子（`is_hydrogen()` 检查），可选保留
- 跳过非 ATOM/HETATM 行

**`read_sdf_atoms(path, molecule_index=0, include_hydrogen=False)`** — SDF 解析器：
- 按 `$$$$` 分隔符分块，每个 block 是一个分子
- 从 counts line（第 4 行，前 3 个字符）读原子数
- 每个原子行前 4 个 token 为 x、y、z、element

**`read_ligand_atoms(path)`** — 自动根据文件后缀选择 PDB 或 SDF reader，支持 `.gz` 压缩。

### `chemistry.py` — 化学规则与判定

**关键函数 `infer_atom_type(element, atom_name, aromatic=None)`** — 将元素符号映射到 ESField 的 11 种原子类型之一：

| 元素 | 条件 | 输出类型 |
|------|------|---------|
| C | 名字含 "AR" 或 aromatic=True | `C_aromatic` |
| C | 其他 | `C_sp3` |
| N | 名字含 "H" | `N_donor` |
| N | 其他 | `N_acceptor` |
| O | — | `O_acceptor` |
| S | — | `S` |
| P | — | `P` |
| F/Cl/Br/I | — | `halogen` |

**`is_compatible_atom_site(atom_type, atomic_number, site_type)`** — 判定原子与位点是否兼容，采用两层规则：

```
第一层 — 类型白名单：
  hydrophobic_cavity → {C_sp3, C_aromatic, halogen, S}
  high_energy_water  → {C_sp3, C_aromatic, halogen, S, O_acceptor, N_donor, N_acceptor}
  stable_water       → {O_acceptor, N_donor, N_acceptor}

第二层 — 原子序数兜底（即使 atom_type 不在白名单中）：
  疏水空腔允许 atomic_number ∈ {6, 9, 16, 17, 35, 53} 即 C/F/S/Cl/Br/I
  水相关位点允许 atomic_number ∈ {7, 8, 15, 16} 即 N/O/P/S
```

**`incompatible_atom_type_for_site(site_type)`** — 为每种位点类型返回一个明确不兼容的 (atom_type, atomic_number) 组合，用于构造 hard negative：
- `hydrophobic_cavity` → `("O_acceptor", 8)`（亲水氧不兼容疏水空腔）
- `stable_water` → `("C_sp3", 6)`（疏水碳不兼容稳定水）
- `high_energy_water` → `("charged", 6)`（带电碳不兼容高能水）

**`is_water_residue(residue_name)`** — 水残基名白名单：`HOH/WAT/H2O/DOD/TIP/SOL`

### `geometry.py` — 轻量几何运算

纯 Python 实现，不依赖 numpy，全部为无副作用的纯函数：
- `distance(a, b)` — 欧几里得距离
- `squared_distance(a, b)` — 平方距离（避免 sqrt 开销）
- `centroid(points)` — 重心
- `gaussian_weight(d, sigma)` — `exp(-d² / (2σ²))`，核心权重函数
- `subtract(a, b)` — 向量差（相对位置）
- `add(a, b)` / `scale(a, f)` — 向量加法/标量乘法
- `norm(a)` — 向量模长

## 三、`src/site_detection/` — 位点检测模块

### `site_schema.py` — 位点数据结构（约 300 行）

**核心 dataclass：`Site`**（frozen，不可变）

```
site_id: int                              — 口袋内唯一 ID
site_type: Literal["high_energy_water",
                   "stable_water",
                   "hydrophobic_cavity"]   — 位点类型
center: (float, float, float)             — 3D 坐标（原始 PDB 坐标系）
radius: float                             — 有效半径 (Å)，必须 >0
score: float                              — 位点能量分数，任意实数
confidence: float                         — 置信度 [0, 1]
source: str                               — 来源标注
features: dict[str, Any]                  — 任意 JSON 可序列化特征
```

**核心 dataclass：`SiteMap`**（frozen）

```
schema_version: str     — "1.0"
protein_id: str         — 蛋白标识
ligand_id: str          — 参考配体标识
pocket_center: (float, float, float)
coordinate_frame: str   — 坐标系标注
sites: tuple[Site, ...] — 不可变 site 序列
```

**关键设计决策**：
- `__post_init__` 中做完整的输入 normalization 和校验。因为 `frozen=True` 阻止了正常赋值，必须用 `object.__setattr__(self, field, value)` 绕过。每个字段经过对应的 `_as_xxx()` 函数做类型转换和范围校验。
- `to_json()` / `from_json()` 实现完整的 JSON 序列化/反序列化，确保 round-trip 等价（`SiteMap.from_json(s.to_json()) == s`）。
- `SchemaValidationError` 包含具体字段名和期望值，方便调试。例如 `"site.radius must be a positive number"`。

### `build_crystal_water_sites.py` — 晶体水位点构建

**核心函数 `build_crystal_water_site_map(protein_pdb, *, ligand_path, ...)`** 的完整处理流程：

1. **读 PDB**：`read_pdb_atoms()` 解析全部原子
2. **`_group_water_oxygens(atoms)`**：按 (chain_id, residue_id, residue_name) 分组合并水氧原子，每个水残基只保留第一个 O 原子
3. **分离蛋白原子**：排除水残基的原子
4. **确定口袋中心**（`_resolve_pocket_center()`）：
   - 优先用传入的 `pocket_center`
   - 其次用 ligand heavy atom centroid
   - 最后用全体 protein centroid
5. **对每个水氧原子**进行三步过滤和分类：
   - 距离口袋中心 > `pocket_radius`（默认 10Å）→ 跳过
   - 距离最近蛋白原子 ≤ `protein_clash_distance`（默认 1.6Å）→ 跳过（水埋在蛋白内部）
   - 统计周围的氢键供体/受体数（`hbond_count`）和疏水接触数（`hydrophobic_count`）
6. **`_classify_water_site(hbond_count, hydrophobic_count, cfg)`** 详细的分类规则：

```python
if hbond_count >= stable_hbond_min (2):
    → "stable_water"
    score = -hbond_count  # 氢键越多 score 越低（越稳定）
    confidence = 0.55 + 0.15 × hbond_count  # 如 2 个氢键 → 0.85
    含义：与蛋白形成 ≥2 个氢键的水是稳定水，不应被配体置换

elif hbond_count <= high_energy_hbond_max (1) or hydrophobic_count >= 3:
    → "high_energy_water"
    score = 0.8 + 0.4 × hydrophobic_count - 0.2 × hbond_count
    confidence = 0.45 + 0.1 × hydrophobic_count + 0.1 × (1 - hbond_count + 1)
    含义：氢键少或处于疏水环境的水是"不愿待着"的高能水，希望被配体置换

else:
    → "stable_water" (保守默认，score=-0.5, confidence=0.5)
```
7. **排序截断**：按 (confidence, |score|) 降序，保留 top-K（默认 20）
8. **`_renumber_sites()`**：重新编号 site_id 为 0..k-1，保证连续

### `parse_fpocket.py` — fpocket 输出解析

**核心函数 `parse_fpocket_site_map(fpocket_dir, *, protein_id, ...)`**：
1. 遍历 fpocket 输出目录下的 `pocket*_atm.pdb`（alpha sphere 伪原子）文件
2. 读 alpha spheres 坐标，计算 centroid 和最大径向距离作为 cavity 的中心和半径
3. **`_read_info_files(root)`**：解析 fpocket 的 `*_info.txt` 信息文件

   关键实现细节：用正则 `r"Pocket\s+(\d+)"` 定位每个 pocket 的信息段，然后对每行 `key: value` 提取数值。例如：
   ```
   Pocket 1 :
     Score : 12.5
     Hydrophobicity score : 0.78
   ```
   → `{1: {"score": 12.5, "hydrophobicity_score": 0.78}}`

4. 每个 pocket → 一个 `hydrophobic_cavity` site：
   - `confidence = min(1.0, 0.35 + 0.03 × alpha_sphere_count + 0.05 × hydrophobicity)`
   - radius 截断到 [0.8, 3.5] Å

### `merge_sites.py` — 位点合并、过滤与排序

**核心函数 `merge_site_maps(site_maps, *, merge_distance=1.0, max_sites=20, ...)`**：

1. **类型优先级**：`high_energy_water(3) > stable_water(2) > hydrophobic_cavity(1)`
2. **过滤**：radius ∈ [0.5, 3.5] 且 confidence ≥ min_confidence
3. **贪心单链聚类**：

   对每个 site（已按 rank 降序排列）：
   - 检查是否与已有 cluster 中任意 site 距离 ≤ `merge_distance`
   - 是 → 加入该 cluster；否 → 新建 cluster

4. **`_merge_cluster(cluster)`** — 把同一 cluster 的多个 sites 合并为一个：

   - **中心**：按 confidence 加权平均（精确浮点计算，非近似）
   ```
   weights = [max(conf, 0.01) for each site]
   center = weighted_average(centers, weights)
   ```
   - **类型**：选 cluster 中优先级最高且总 confidence 最大的类型
   - **半径**：取 cluster 中最大值
   - **score**：confidence 加权平均
   - **confidence**：min(1.0, max(conf) + 0.05 × (cluster_size - 1))
     多位点重合提升置信度的设计依据：多个独立方法在同一位置检测到位点，可靠性更高
   - **source**：用 `+` 连接所有来源（如 `"crystal_water_rule+fpocket"`）
   - **features**：记录融合的 site 数量和原始 site_id 列表

5. 排序截断：按 rank key 保留 top-K

### `build_atom_site_pairs.py` — 正负样本构建器

**核心函数 `build_atom_site_pairs(ligand_atoms, site_map, *, config)`** 返回 `list[AtomSitePair]`。

**正样本构造（`_build_positive_pairs`）**：

```
对每个配体原子:
  对每个位点:
    距离 = distance(atom.coord, site.center)
    阈值 = site.radius + positive_padding（默认额外 0.5Å）
    if 距离 ≤ 阈值 AND is_compatible_atom_site(atom, site):
      记录为候选
  候选按距离升序排序
  取 top-2（max_positive_sites_per_atom）作为正样本

  label_strength = site.confidence × gaussian_weight(d, sigma)
  其中 sigma = max(0.1, sigma_scale × site.radius)
  含义：位点置信度越高 + 原子越靠近位点中心 → label_strength 越高
```

**负样本构造（`_build_negative_pairs`）**——五种类型：

| 类型 | 构造方式 | 设计意图 |
|------|---------|---------|
| **hard_negative** | 距离近（d ≤ radius+padding）但 `is_compatible()` 返回 False | 最难区分的负样本，训练网络关注类型兼容性而非仅距离 |
| **distance_corruption** | 距离远（d > radius+padding）的任意 atom-site pair | 网络应学会远距离 pair 不兼容 |
| **atom_type_corruption** | 取正样本的 atom+site，将 atom_type 替换为 `incompatible_atom_type_for_site()` 返回的明确不兼容类型 | 固定位置和位点，强制作类型不兼容 |
| **random_type_corruption** | 随机选取 atom+site 对，若碰巧是正样本则 corrupt 类型 | 补充随机采样 |
| **random_negative** | 纯随机 atom+site pair（非正样本） | 随机负样本 |

**容量控制**：`target_count = min(positives × negative_ratio, ligand_atoms × sites 总数)`，确保不会无限循环也不会生成过多重复负样本。

### `distance_encoding.py` — RBF 距离编码

**`rbf_encode(distances, num_bins=16, cutoff=6.0)`**：

- 在 [0, cutoff] 范围内均匀放置 `num_bins` 个等间距的高斯径向基函数中心
- 每个距离值被编码为一个 16 维向量
- 公式：`exp(-(d - center_i)² / (2 × width²))`
- RBF 编码比直接输入单个距离值给 MLP 提供了更丰富的距离表示能力——MLP 可以从多个高斯基函数的激活模式中学习距离的非线性变换

**`require_torch()`**：惰性导入 PyTorch。若未安装给出清晰错误信息而不是 cryptic ImportError。

### `potential_network.py` — 兼容性势能网络（ESField 核心模型）

**`CompatibilityPotential(nn.Module)`** 是 ESField 的核心神经网络。

**输入特征**（拼接维度 = 32 + 32 + 3 + 1 + 16 + 2 = 86）：

```
atom_embedding:      32d — Embedding(11, 32)
site_embedding:      32d — Embedding(4, 32)
relative_position:   3d  — (x_atom - x_site) / site_radius（归一化相对坐标）
distance_scaled:     1d  — distance / site_radius（归一化距离）
rbf_encoding:        16d — 高斯径向基编码
scalar_features:     2d  — [site_radius, site_confidence]
```

**为什么输入同时包含 relative_position（3维方向）和 distance（1维标量）+ RBF？**
- relative_position 提供了方向信息，使网络能学习各向异性的位点偏好（如"在疏水空腔左侧比右侧更兼容"）
- distance + RBF 提供了丰富的距离表示，弥补 MLP 对距离建模的不足
- 两者互补，让网络同时利用方向信息和距离信息

**网络结构**：

```
Linear(86, 256) + SiLU
→ ResidualMLPBlock × 4
  ┌─ Linear(256, 256) + SiLU + Linear(256, 256)
  └─ + residual connection → LayerNorm
→ LayerNorm + Linear(256, 1)
→ energy_clip × tanh(output / energy_clip)  软裁剪到 [-5, 5]
```

**`ResidualMLPBlock`**：标准 Pre-LN 残差块 `LayerNorm(x + MLP(x))`。4 层残差块比普通 4 层 MLP 更好训练，梯度流更稳定。

**输出的含义**：标量 energy，正值表示不兼容（高势能）、负值表示兼容（低势能）。

**`tensor_batch_from_pairs(pairs, device)`**：将 `AtomSitePair` 列表转为 PyTorch tensor dict，供训练循环使用。

### `losses.py` — 损失函数和评估指标

**`margin_energy_loss(energy, label, *, label_strength, margin_pos=-1.0, margin_neg=1.0)`** — 主损失：

```python
# 正样本：鼓励 energy 低于 margin_pos（即低于 -1.0）
pos_loss = softplus(energy - margin_pos)
# 负样本：鼓励 energy 高于 margin_neg（即高于 1.0）
neg_loss = softplus(margin_neg - energy)
# label_strength 对正样本做软加权（不确定的正样本贡献小），负样本权重固定为 1
weights = where(label > 0.5, label_strength.clamp_min(0.05), 1.0)
```

**为什么用 softplus 而不是 MSE？** softplus 在满足 margin 后梯度接近零（不会继续强行推），MSE 会一直推。softplus 让网络"达标即可"，减少过拟合。

**`logistic_energy_loss(energy, label, *, label_strength)`** — 备选损失：

```python
logit = -energy  # energy 越低 → 兼容概率越高
loss = BCE_with_logits(logit, label, weight=label_strength)
```

**`gradient_penalty(energy, coordinates, *, target_norm=0.0)`** — 可选正则化项，限制 `||grad_x E||` 不过大。`target_norm=0` 表示鼓励梯度尽量小（平滑势能面）。

**`binary_auc(labels, scores)`** — 不依赖 sklearn 的纯 Python AUC 实现。O(n²) 成对比较，仅在验证集使用所以数据量可控。

**`ranking_accuracy(labels, energies)`** — 任意正样本能量低于任意负样本的比例。比 AUC 更直观：65% 表示随机抽一个正样本和一个负样本，正样本能量更低的概率是 65%。

## 七、`src/guidance/` — 推断期引导模块

### `energy_guidance.py` — 核心引导引擎（ESField 最关键的组件）

**`EnergyGuidance` 类** 负责在推断期计算 site-aware 势能并生成坐标梯度。

**`total_energy(coordinates, *, site_map, atom_type_indices=None, atom_type_probs=None)`**：

总势能公式：
```
E_total = Σ_i Σ_j w_ij × E_phi(atom_i, site_j)
```

**权重 w_ij 的设计**（关键技术）：

```python
# w_ij 是三部分的乘积：

# 1. 高斯权重（核心衰减）
w_gauss = exp(-d² / (2σ²))
# σ = sigma_scale × site_radius
# 距离越远，权重指数衰减，平滑过渡

# 2. 软截断（关键技术！避免梯度不连续）
w_cutoff = sigmoid(8 × (cutoff - d))
# cutoff = max(4.0Å, cutoff_radius_scale × site_radius)
# 不直接使用 "if d < cutoff" 硬截断！
# sigmoid(8x) 在 cutoff 附近快速但平滑地过渡到 0

# 3. 位点置信度
w_ij = w_gauss × w_cutoff × site_confidence
```

**为什么用 sigmoid 软截断而不用硬阈值？** 硬阈值 `if d < cutoff` 在 cutoff 边界处导数不连续（导数从有限值跳变到 0），会导致 ODE 积分时坐标梯度突变，破坏分子几何。sigmoid(8×(cutoff-d)) 在 cutoff 附近提供平滑但迅速的过渡，保证梯度处处连续。

**处理原子类型不确定性**：

当 `atom_type_probs`（概率分布而非离散类型）传入时：
```python
# 对 vocab 中每种原子类型分别计算 E_phi
energies_by_type = [E_phi(atom_type_k, ...) for k in vocab]
# 按概率加权求和
pair_energy = Σ_k P(type_k | x_i, t) × E_phi(x_i, type_k, site_j)
```
这样即使生成初期类型不确定，也能以期望值的形式提供 soft guidance。

当 `atom_type_indices`（离散类型）传入时，直接按该类型计算 E_phi。

**`coordinate_gradient(coordinates, *, site_map, ...)`**：

```python
coords = coordinates.detach().clone().requires_grad_(True)
energy = self.total_energy(coords, ...)
grad = torch.autograd.grad(energy, coords)[0]
grad = clip_by_norm(grad, max_norm)  # 逐原子 norm 裁剪
return energy.detach(), grad.detach()
```

**为什么要 detach？**
- 每个 ODE step 独立计算梯度，不保留跨 step 的计算图
- 如果不 detach，几百个 ODE step 的计算图会累积，导致显存爆炸
- 这是 ESField 的显存安全关键设计

**`clip_by_norm(grad, max_norm)`**：对每个原子的梯度向量做 norm 裁剪，防止个别原子受到过大引导力。`scale = clamp(max_norm / norm, max=1.0)` 确保只缩不放。

**`guided_velocity(base_velocity, coordinates, *, t, site_map, ...)`**：

```python
lambda_t = guidance_lambda(t)  # 当前时间步的引导强度
if lambda_t == 0:
    return base_v  # 无需引导（t 在 guidance 区间外）
energy, grad = coordinate_gradient(coordinates, ...)
guided_v = base_v - lambda_t × grad  # 向 E_total 减小方向修改速度场
return guided_v, diagnostics  # 含 lambda_t, E_total 值, grad norm
```

### `lambda_schedule.py` — 引导强度调度

**`guidance_lambda(t, *, lambda_max, guidance_start, guidance_end, schedule)`**：

四种调度策略对比：

| 策略 | 公式 | 特点 |
|------|------|------|
| **sigmoid**（推荐） | `lambda_max / (1 + exp(-12×(x-0.5)))` | 中段快速启停，首尾平滑 |
| **cosine** | `lambda_max × 0.5 × (1 - cos(π×x))` | 钟形，全程平滑 |
| **linear** | `lambda_max × x` | 简单线性 |
| **constant** | `lambda_max` | 全程恒定（仅用于测试） |

**为什么不在全程开启引导？**
- t 接近 0（早期 denoising）：坐标噪声极大，site gradient 会把未成形分子拉散
- t 接近 1（晚期）：结构已精细，过强引导破坏键长键角
- 只在 `t ∈ [guidance_start, guidance_end]` 开启，默认 [0.35, 0.90]，中后期引导

### `flow_matching_guidance.py` — Flow Matching 专用 hook

薄封装 `apply_site_guidance_to_velocity(guidance, base_velocity, coordinates, *, t, site_map, atom_type_indices=None, atom_type_probs=None)`。

**调用此函数的位置**：在 flow matching 的 ODE 积分循环中，每个 step 在计算 base_velocity 之后、执行 `ode_solver_step` 之前调用：
```python
base_v, atom_type_probs = model.velocity(x, protein, t)
guided_v, diag = apply_site_guidance_to_velocity(
    guidance, base_v, x, t=t, site_map=site_map,
    atom_type_probs=atom_type_probs,
)
x = ode_solver_step(x, guided_v, t)
```

### `latent_guidance.py` ★ v7 新增 (~580 行) — 层次化 Latent Guidance 核心

v7 最核心的模块，包含：

**`SiteCompatibilityEnergy`** — 可微的位点-原子兼容性能量函数。
- 硬编码 4×11 兼容性矩阵（不学习，基于化学规则）
- 能量 = −Σ compat × exp(−d²/(2σ²)), σ=3.0Å
- 对坐标 x_t 可微（用于 Metadiffusion 式引导）
- 支持 soft type probabilities 和 hard type indices
- `compute_gradient()`: 返回能量值和 ∇E（带 per-atom gradient clipping）
- `compute_per_site_scores()`: 每位点单独得分（用于诊断）

**`apply_latent_guidance()`** — Metadiffusion 速度修正：
- `v_guided = v_pred − λ_eff × ∇E`, λ_eff = λ × η_kts
- 梯度仅作用于坐标（原子类型由 TypeGuidanceBias 单独处理）

**`TypeGuidanceBias`** — 原子类型 logit 偏置：
- `logits' = logits + β × Σ_j compat(env_j, type) × gauss(d_ij)`
- 软偏置：靠近 hydrophobic site → C/halogen logit 增加；靠近 polar unsatisfied → O/N logit 增加

**辅助函数**：
- `build_site_energy_from_map()`: 从 site_map dict 构建 SiteCompatibilityEnergy（含环境过滤、置信度过滤、top-k）
- `harmonic_restraint_energy()`: 锚原子简谐约束 E = k × Σ‖x_i − x_i^fixed‖²
- `classify_hew_environment()`, `hew_env_to_idx()`: HEW 环境分类

### `kinetic_trajectory_shaping.py` ★ v7 新增 (~200 行) — KTS 时变调度器

**`KTSScheduler`** — 实现 Kinetic Trajectory Shaping 时变缩放因子：
```
if t < τ_split: η = 1 + α₀ × (1 − t/τ_split)       (early boost: 线性衰减到 1)
else:           η = 1 − β₀ × (exp(k×(t−τ_split))−1)  (late damp: 指数衰减)
```
- t ∈ [0,1]: 0=noise, 1=data
- 默认 α₀=β₀=0.01, τ_split=0.6, k=3.0
- `compute_schedule()`: 预计算全轨迹 η 值

**`CompositeScheduler`** — 组合 KTS × guidance λ schedule：
- λ_eff(t) = λ_base × λ_schedule(t) × η_kts(t)

### `two_stage_generation.py` ★ v7 新增 (~950 行) — 两阶段生成编排

v7 的核心流程控制器，包含：

**数据类**：

## 九、`src/evaluation/` — 评估模块

### `site_matching.py` — 专属位点指标（ESField 的核心评估）

**`evaluate_site_matching(ligand_atoms, site_map)`** 返回 `SiteMatchingMetrics`：

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| **SOR** | occupied_sites / total_sites | 有任意配体原子占据的目标位点比例 |
| **CASMR** | compatible_occupied / occupied | 被占据位点中原子类型兼容的比例 |
| **HEWRR** | 兼容占据的高能水 / 高能水总数 | 高能水被成功"挤走"的比例，越高越好 |
| **SWPP** | 不兼容占据的稳定水 / 稳定水总数 | 稳定水被破坏的比例，越低越好 |
| **HCFS** | mean(max_i gaussian_weight(d_i, r_j)) | 疏水空腔被疏水原子填充的软分数，越高越好 |

**"占据"的定义**：有配体原子距离位点中心 ≤ site.radius。

### `site_occupancy.py` ★ v7 新增 (~320 行) — 位点占据评估指标

专为 v7 两阶段生成设计的轻量评估指标（零学习参数，纯几何+化学规则）：

**`direct_occupancy_rate()`** — 占据至少一个 HEW 位点的分子比例：
- 对每个分子，检查是否存在兼容类型原子（基于原子序数而非 atom type vocabulary）距离任意 HEW site ≤ threshold (默认 2.5Å)
- 返回：occupancy_rate, n_occupied, per_mol 统计

**`best_compatible_distance()`** — 每位点最近兼容原子距离：
- 对每个 HEW site，在所有生成分子中找最近的兼容原子
- 返回：per_site 详情（site_id, environment, best_distance, best_atomic_num）、统计量

**`site_occupancy_summary()`** — 综合诊断报告：
- 合并 direct_occupancy_rate + best_compatible_distance 为单一 dict

**`evaluate_sdf_occupancy()`** — 便捷函数：从 SDF 文件 + site_map JSON 直接计算全部指标。

### `molecule_quality.py` — 分子质量代理指标

- `heavy_atom_count`：重原子数
- `qed`：drug-likeness（需 RDKit），QED 取值范围 [0, 1]，越高越好
- `sa_score`：合成可及性（需 RDKit + sascorer），越低越好
- 当 RDKit 未安装时自动标注 `rdkit_status: "rdkit_not_installed"` 而非崩溃

### `failure_analysis.py` — 失败模式自动检测

按阈值检测常见失败模式并生成中文警告：
- SOR < 0.2 → "位点占据不足或 site map 过于严格"
- CASMR < 0.5 → "生成原子类型与位点类型匹配不足"
- SWPP > 0.2 → "stable water 可能被不兼容原子占据"
